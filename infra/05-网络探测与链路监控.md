# 05-网络探测与链路监控（自动纳管）

本阶段目标：在现有 `VictoriaMetrics + Grafana` 基础上，补齐 **主动探测 + 底层链路指标**，并让新增节点默认纳管。

## 1. 目标与边界

- 第一阶段：主动探测
  - 节点间 `Pod` 路径
  - `ClusterIP` 基线路径
  - 公网入口 `80/443`
  - apiserver `6443`
  - `ICMP`
- 第二阶段：底层链路指标
  - `WireGuard/Kilo` peer
  - 网卡 `drops/errors`
  - `softnet`
  - `TCP retransmits`
  - `conntrack`
- 不引入 `eBPF`
- 所有组件保持 `ClusterIP`，不新增公网暴露

## 3. 自动纳管规则

- 所有 `Ready` 且 `kubernetes.io/os=linux` 的节点，默认纳入内部探测与底层链路指标
- 如果节点有 annotation `homelab.panda/public-endpoint=<dns-or-ip>`：
  - 自动生成 `80/443`
  - 自动生成 `ICMP`
- 如果节点有 annotation `homelab.panda/apiserver-endpoint=true`：
  - 自动生成 `https://<public-endpoint>:6443/livez`
- 如果节点有 label `homelab.panda/network-monitor=disabled`：
  - 跳过主动探测自动纳管
- 删除节点时：
  - reconciler 自动删除对应 `VMProbe`

当前节点 contract：

- 必须有 `region` label
- 推荐维护：
  - `homelab.panda/public-endpoint`
  - `homelab.panda/apiserver-endpoint`

## 4. 第一阶段：主动探测

组件：

- `network-blackbox-exporter`：DaemonSet，每节点 1 个实例
- `network-probe-reconciler`：CronJob，按节点列表自动生成 `VMProbe`

探测范围：

- `internal`：每个 source node 到每个 target node 的 `network-blackbox-exporter` `PodIP`
- `internal`：每个 source node 到 `network-blackbox-exporter.monitoring.svc:9115/-/healthy`
- `public`：每个 source node 到所有带 `public-endpoint` 的 `http://` / `https://`
- `apiserver`：到控制面节点 `https://<public-endpoint>:6443/livez`
- `icmp`：节点间 public endpoint 的双向 ping

关键 labels：

- `source_node`
- `target_node`
- `source_region`
- `target_region`
- `probe_scope`
- `module`
- `target_endpoint`

## 5. 第二阶段：底层链路指标

组件：

- `network-wireguard-exporter`：DaemonSet，每节点 1 个实例
- `kilo-metrics`：直接抓取 `kube-system/kilo` DaemonSet 的 `1107` metrics 端口
- 现有 `node-exporter`：继续提供网络类 collector 指标
- `VMRule`：网络专用告警规则

重点指标：

- `wireguard_latest_handshake_seconds`
- `wireguard_sent_bytes_total`
- `wireguard_received_bytes_total`
- `kilo_nodes`
- `kilo_peers`
- `kilo_errors_total`
- `kilo_reconciles_total`
- `node_network_receive_drop_total`
- `node_network_transmit_drop_total`
- `node_network_receive_errs_total`
- `node_network_transmit_errs_total`
- `node_softnet_dropped_total`
- `node_netstat_Tcp_RetransSegs`
- `node_nf_conntrack_entries`

## 7.1 Dashboard 解读

### `Infra / Inter-Node Network`

- 用途：看 **节点到节点** 的方向性网络质量，而不是按 endpoint 混在一起看
- 推荐看法：
  - `Internal Probes OK / Failed`：只看集群内部链路
  - `Public Probes Failed`：只看 `80/443`
  - `Control Plane / ICMP Failed`：只看 `6443` 和 `ICMP`
  - `Internal Success by Direction`：判断 `source_node -> target_node` 哪个方向有问题
  - `Latest Failing Probes`：定位具体失败项
- 过滤建议：
  - `probe_scope=internal`：只看跨节点 overlay / Pod 路径
  - `probe_scope=public`：只看公网 `80/443`
  - `probe_scope=apiserver`：只看 `6443`
  - `probe_scope=icmp`：只看 ping
  - `module` 变量必须配合 `probe_scope` 看，避免不同协议聚合出 `50 / 75 / 80` 这种不直观结果

### `Infra / Endpoint Reachability`

- 用途：看 **具体 endpoint** 的可达性，而不是看节点方向
- 关键变化：
  - 成功率现在按 `target_endpoint + module` 维度统计，避免 `http / https / icmp` 混在一个 endpoint 上
  - 增加 `source_node` 和 `module` 变量，便于单独看某个源节点或协议
- 推荐看法：
  - `Success Rate by Endpoint and Module`：先判断哪种协议失败
  - `Latest HTTP Status Codes`：只看 `http_2xx / https_2xx / https_apiserver_livez`
  - `Latest Failing Endpoints`：快速定位最后失败项

## 8. 新增节点 SOP

新增节点默认纳管，但要满足：

1. 节点加入集群并 `Ready`
2. 节点带 `region` label
3. 若有公网入口，补 annotation：

```bash
kubectl annotate node <NODE> homelab.panda/public-endpoint=<host-or-ip> --overwrite
```

4. 若节点是控制面入口，再补：

```bash
kubectl annotate node <NODE> homelab.panda/apiserver-endpoint=true --overwrite
```

5. 等待下一轮 reconciler（或手工触发 CronJob）后，自动出现：
  - 主动探测
  - WireGuard / Kilo / NIC / conntrack 指标
  - 对应 network dashboards

## 9. 告警规则

第一阶段：

- `probe_success == 0`
- apiserver `6443` 不可达
- 内部全网格探测失败
- 公网入口失败

第二阶段：

- WireGuard handshake stale
- 网卡 drops/errors 持续增长
- `TCP retransmits` 异常升高
- `softnet dropped` 持续非零
- conntrack 使用率过高
