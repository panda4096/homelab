# 05-网络探测与链路监控（自动纳管）

本阶段目标：在现有 `VictoriaMetrics + Grafana` 基础上，补齐 **主动探测 + 底层链路指标**，并让新增节点默认纳管。

## 1. 目标与边界

- 第一阶段：主动探测
  - 节点间 `Pod` 路径
  - `ClusterIP` 基线路径
  - 公网入口 `80/443`
  - apiserver `6443`
  - `ICMP`
- 第二阶段：底层链路指标
  - `WireGuard/Kilo` peer
  - 网卡 `drops/errors`
  - `softnet`
  - `TCP retransmits`
  - `conntrack`
- 不引入 `eBPF`
- 所有组件保持 `ClusterIP`，不新增公网暴露

## 3. 自动纳管规则

- 所有 `Ready` 且 `kubernetes.io/os=linux` 的节点，默认纳入内部探测与底层链路指标
- 如果节点有 annotation `homelab.panda/public-endpoint=<dns-or-ip>`：
  - 自动生成 `80/443`
  - 自动生成 `ICMP`
- 如果节点有 annotation `homelab.panda/apiserver-endpoint=true`：
  - 自动生成 `https://<public-endpoint>:6443/livez`
- 如果节点有 label `homelab.panda/network-monitor=disabled`：
  - 跳过主动探测自动纳管
- 删除节点时：
  - reconciler 自动删除对应 `VMProbe`

当前节点 contract：

- 必须有 `region` label
- 推荐维护：
  - `homelab.panda/public-endpoint`
  - `homelab.panda/public-ip`（如果节点状态里没有可用的 `ExternalIP` / `k3s.io/external-ip`）
  - `homelab.panda/apiserver-endpoint`

## 4. 第一阶段：主动探测

组件：

- `network-blackbox-exporter`：DaemonSet，每节点 1 个实例
- `network-probe-reconciler`：CronJob，按节点列表自动生成 `VMProbe`
- `edge_public_tcp`：自动生成广州公网代理入口端口探针（`11080/11081/18388/11800`）
- `edge_relay_tcp`：自动生成广州入口到新加坡 `Kilo IP` 代理端口探针（`11080/11081/18388`）

探测范围：

- `internal`：每个 source node 到每个 target node 的 `network-blackbox-exporter` `PodIP`
- `internal`：每个 source node 到 `network-blackbox-exporter` Service 的真实 `ClusterIP`
- `public`：每个 source node 到所有节点公网 **IP** 的 `http://` / `https://`
- `apiserver`：到控制面节点公网 **IP** 的 `https://<public-ip>:6443/livez`
- `icmp`：节点间公网 **IP** 的双向 ping

说明：

- 这里刻意优先使用 `public-ip` / `ExternalIP`，而不是域名
- 目的不是做 DNS 监控，而是把 **网络连通性** 与 **域名解析问题** 分开
- 如果 `public-ip` 缺失，reconciler 才会退回到 `public-endpoint` 主机名

关键 labels：

- `source_node`
- `target_node`
- `source_region`
- `target_region`
- `probe_scope`
- `module`
- `target_endpoint`

## 5. 第二阶段：底层链路指标

组件：

- `network-wireguard-exporter`：DaemonSet，每节点 1 个实例
- `kilo-metrics`：直接抓取 `kube-system/kilo` DaemonSet 的 `1107` metrics 端口
- 现有 `node-exporter`：继续提供网络类 collector 指标
- `VMRule`：网络专用告警规则

重点指标：

- `wireguard_latest_handshake_seconds`
- `wireguard_sent_bytes_total`
- `wireguard_received_bytes_total`
- `kilo_nodes`
- `kilo_peers`
- `kilo_errors_total`
- `kilo_reconciles_total`
- `node_network_receive_drop_total`
- `node_network_transmit_drop_total`
- `node_network_receive_errs_total`
- `node_network_transmit_errs_total`
- `node_softnet_dropped_total`
- `node_netstat_Tcp_RetransSegs`

## 7.1 Dashboard 解读

### `Infra / Inter-Node Network`

- 用途：看 **节点到节点** 的方向性网络质量，而不是按 endpoint 混在一起看
- 推荐看法：
  - 顶部计数卡已移除，避免和成功率/耗时趋势重复
  - `内网节点间 Pod 探测成功率`：按当前 dashboard 时间范围动态调整统计窗口（使用 `$__range`），不再固定 5 分钟，也不再只看最后一次结果
  - `公网入口成功率（按方向）` / `API Server 成功率（按方向）` / `ICMP 成功率（按方向）`：外部链路成功率按类型拆开看，统计窗口随当前时间范围变化（不是 `$__interval` 采样步长）
  - `Latest Failing Probes`：定位具体失败项
  - 当前方向类面板默认隐藏 `source_node == target_node` 的自环探测，只保留真正的跨节点视图
  - 这里的“节点间 Pod 探测”指：`source_node` 上 blackbox Pod 到 `target_node` 上 blackbox Pod 的 `/-/healthy` HTTP 探测，不是业务 Pod 端到端事务
- 过滤建议：
  - `probe_scope=internal`：只看跨节点 overlay / Pod 路径
  - `probe_scope=public`：只看公网 `80/443`
  - `probe_scope=apiserver`：只看 `6443`
  - `probe_scope=icmp`：只看 ping
  - `module` 变量必须配合 `probe_scope` 看，避免不同协议聚合出 `50 / 75 / 80` 这种不直观结果

### `Infra / Endpoint Reachability`

- 用途：看 **具体 endpoint** 的可达性，而不是看节点方向
- 关键变化：
  - 成功率现在按 `target_endpoint + module` 维度统计，避免 `http / https / icmp` 混在一个 endpoint 上
  - 增加 `source_node` 和 `module` 变量，便于单独看某个源节点或协议
- 额外说明：
  - 这里的 `icmp` / `public` / `apiserver` 默认优先展示 **IP endpoint**
  - 如果刚改过 probe 目标，旧 hostname 结果可能会在 lookback 窗口内短暂残留几分钟
  - `https_apiserver_livez` 允许 `200` 和 `401`
    - 这套 k3s 对公网 `https://<public-ip>:6443/livez` 的匿名访问会返回 `401`
    - 对网络探测来说，这表示 **TLS 与 TCP 已通，apiserver 有响应**
    - 因此这里把 `401` 视为“网络层健康”，而不是认证层失败
- 推荐看法：
  - `Success Rate by Endpoint and Module`：先判断哪种协议失败
  - `Latest HTTP Status Codes`：只看 `http_2xx / https_2xx / https_apiserver_livez`
  - `Latest Failing Endpoints`：快速定位最后失败项

### `Infra / Edge Gateway`

- 用途：专门排障 `广州入口 -> Kilo -> 新加坡出口` 的代理链路
- 推荐看法：
  - 顶部 4 个状态卡先看 `HTTP CONNECT`、`SOCKS5` 和出口 IP 是否正确
  - `端到端探针耗时趋势` 用来判断“代理整体变慢了没有”
  - `TCP 建连耗时趋势` 用来区分是广州公网入口慢，还是 `GZ -> SG` relay 建连慢
  - `当前失败的 TCP 探针` 用来直接定位哪一个端口失败
  - `当前观测到的出口 IP` 用来确认是不是仍然从 `sg` 出公网

## 8. 新增节点 SOP

新增节点默认纳管，但要满足：

1. 节点加入集群并 `Ready`
2. 节点带 `region` label
3. 若有公网入口，补 annotation：

```bash
kubectl annotate node <NODE> homelab.panda/public-endpoint=<host-or-ip> --overwrite
```

4. 若节点是控制面入口，再补：

```bash
kubectl annotate node <NODE> homelab.panda/apiserver-endpoint=true --overwrite
```

5. 等待下一轮 reconciler（或手工触发 CronJob）后，自动出现：
  - 主动探测
  - WireGuard / Kilo / NIC / conntrack 指标
  - 对应 network dashboards

## 9. 告警规则

第一阶段：

- `probe_success == 0`
- apiserver `6443` 不可达
- 内部全网格探测失败
- 公网入口失败
- `edge_public_tcp` 失败
- `edge_relay_tcp` 失败

第二阶段：

- WireGuard handshake stale
- 网卡 drops/errors 持续增长
- `TCP retransmits` 异常升高
- `softnet dropped` 持续非零
- conntrack 使用率过高

代理链路观测：

- `HTTP CONNECT` 端到端探针失败
- `SOCKS5` 端到端探针失败
- 代理端到端耗时持续过高
- 出口 IP 与预期不一致
