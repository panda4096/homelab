# 02-集群搭建（两节点跨地域 k3s 单集群，gz server + sg agent）

本 Runbook 以 `infra/` 为 **source of truth**：库存、版本锁定、manifest/values、端口清单、变更单都在仓库里维护。

- 节点清单：`infra/inventory/hosts.yaml`

- 端口清单：`infra/03-端口与安全组.md`

- 代理网关架构：`infra/06-跨地域代理网关架构.md`

> 原则：敏感信息不入库（node-token、kubeconfig 私钥/证书等），只写占位符。

## 1. 架构概览

### 1.1 节点与角色

| 节点 | 角色 | region label | SSH |
|---|---|---|---|
| gz.butcoder.com | k3s server（控制面） | `region=gz` | `ssh gz.butcoder.com` |
| sg.butcoder.com | k3s agent（工作节点） | `region=sg` | `ssh sg.butcoder.com` |

- k3s API Endpoint（默认）：`https://gz.butcoder.com:6443`
- 约定：为便于识别，我们把 `kubectl get nodes` 的 `ROLES` 显示统一为 `master/worker`（通过 `node-role.kubernetes.io/*` labels；变更记录：`infra/changes/20260302-node-roles.md`）

### 1.2 网络设计（为什么用 Kilo）

- k3s 安装时禁用 flannel（自定义 CNI）：由 Kilo 提供 CNI + WireGuard mesh，让跨地域节点 PodIP/ClusterIP 互通。
- 预期现象：k3s server 刚装好时，部分 Pod 可能 Pending（因为 CNI 还没装），安装 Kilo 后应恢复正常。

### 1.3 目录分层（为什么入口网关不再放在 `k3s/` 下）

- `infra/k3s/`：集群引导层，只放 k3s 自身、Kilo、备份、kubeconfig 拉取等资产。
- `infra/platform/`：平台层，放 ingress、监控、日志、证书管理等集群就绪后的公共组件。
- `infra/apps/`：业务层，后续应用 manifest/Helm values 建议放这里。

### 1.4 安全约束（强约束）

- 只开放运行所需端口（见 `infra/03-端口与安全组.md`），并尽量限制来源 IP。
- 默认不暴露任何“通用代理/管理入口”到公网；如需建设代理网关，按 `infra/06-跨地域代理网关架构.md` 单独实施。

### 2.3 安装步骤（SOP：两节点 gz+sg）

> 实际执行时：把关键命令与关键输出摘要记录在变更单（例如 `infra/changes/20260301-k3s-init.md`）。

#### 2.3.1 Preflight（gz / sg）

在两台机器分别执行：

```bash
set -euxo pipefail
date
uname -a
lsb_release -a || cat /etc/os-release
df -h
mount | grep " / "
```

验收：

- 根分区必须是 `rw`
- 至少 10GiB 可用空间

安装基础工具（两台都执行）：

```bash
sudo apt-get update
sudo apt-get install -y curl ca-certificates jq sqlite3
sudo apt-get install -y wireguard-tools iptables || true
```

#### 2.3.2 安装 k3s server（gz，禁用 flannel，准备装 Kilo 作为 CNI）

在 `gz` 执行：

```bash
export TMPDIR=/var/tmp
API_ENDPOINT="gz.butcoder.com"

curl -sfL https://get.k3s.io | sudo \
  INSTALL_K3S_VERSION="" \
  K3S_DATA_DIR="/var/lib/rancher/k3s" \
  INSTALL_K3S_EXEC="server \
    --tls-san ${API_ENDPOINT} \
    --disable traefik \
    --flannel-backend=none \
    --disable-network-policy \
    --write-kubeconfig-mode=644" \
  sh -
```

验证（CNI 未安装前 Pending 属预期）：

```bash
sudo systemctl status k3s --no-pager
sudo k3s kubectl get nodes -o wide
sudo k3s kubectl get pods -A -o wide
sudo k3s --version
```

##### 2.3.2.1 跨地域（gz/sg 私网不互通）时：固定 apiserver advertise-address（推荐）

背景：跨地域节点通常无法直连对方的私网 IP。如果集群内部 `kubernetes.default` 的 Endpoints 指向了 `gz` 的私网 IP，会导致 `sg` 上的组件（尤其是 CNI/Kilo）在“尚未建好 WireGuard mesh”之前无法访问 apiserver，从而形成启动闭环。

在 `gz` 执行（**不要**设置 `node-ip` 为公网 IP；若公网 IP 不在网卡上会导致 kubelet TLS SAN 不匹配，进而 `kubectl logs/exec` 失败）：

```bash
sudo mkdir -p /etc/rancher/k3s
cat <<'EOF' | sudo tee /etc/rancher/k3s/config.yaml >/dev/null
advertise-address: 106.55.163.135
node-external-ip: 106.55.163.135
EOF

sudo systemctl restart k3s

# 验证：kubernetes service 的 endpoint 应为公网 IP（而非 10.x 私网）
sudo k3s kubectl -n default get endpoints kubernetes -o jsonpath='{.subsets[*].addresses[*].ip}{"\n"}'
```

读取 `node-token`（只用于终端 join；不要写入 repo）：

```bash
sudo cat /var/lib/rancher/k3s/server/node-token
```

#### 2.3.3（推荐）在工程目录维护 kubeconfig（用于在本机执行 kubectl/helm）

> kubeconfig 含客户端证书/私钥，属于敏感信息：统一放在 `infra/.secrets/` 管理。当前目录约定与文件边界见 `infra/.secrets/README.md`。

```bash
bash infra/k3s/scripts/fetch-kubeconfig.sh
export KUBECONFIG="$(pwd)/infra/.secrets/homelab-k3s.yaml"
kubectl get nodes -o wide
```

#### 2.3.4 安装 Kilo（CNI + WireGuard mesh）

推荐（在操作机执行，使用 repo 内文件）：

```bash
kubectl apply -f infra/k3s/manifests/kilo-crds.yaml
kubectl apply -f infra/k3s/manifests/kilo-k3s.yaml
kubectl get crd peers.kilo.squat.ai
kubectl -n kube-system get ds/pods -o wide | grep -i kilo || true
kubectl get pods -A -o wide
```

> 说明：如果 `gz` 无法直接访问外部镜像仓库，Kilo 组件会出现 `ImagePullBackOff`。
> 当前优先做法是让 `gz` 的 `k3s/containerd` 经本机 `11081` 的 HTTP CONNECT 入口走新加坡出口代理完成拉取。
>
> 1) 在 `gz` 写入 `/etc/systemd/system/k3s.service.env`
> 2) 设置 `HTTP_PROXY` / `HTTPS_PROXY` 指向 `http://edge-user:<password>@127.0.0.1:11081`
> 3) 设置 `NO_PROXY` 覆盖 `127.0.0.1`、集群网段、`*.svc`、`*.cluster.local`、节点域名/IP
> 4) `sudo systemctl daemon-reload && sudo systemctl restart k3s`
>
> 仍可作为 fallback 的方案：
>
> 1) 配置 k3s registry mirror（例如把 `docker.io` mirror 到可达的 `registry.rancher.com`），并重启 k3s
> 2) 将镜像在可出网机器上拉取后导入到 `gz` 的 containerd
>
> 本仓库 vendored 的 `infra/k3s/manifests/kilo-k3s.yaml` 已将 `imagePullPolicy` 设置为 `IfNotPresent`，便于必要时离线导入镜像。

#### 2.3.5 加入 k3s agent（sg）

在 `sg` 执行（token 只在终端/服务器上短暂使用；不要写入 repo）。建议使用 `K3S_TOKEN_FILE` 避免 token 出现在命令行与 history：

```bash
sudo mkdir -p /etc/rancher/k3s
sudo sh -c 'umask 077; cat > /etc/rancher/k3s/node-token'
# ↑ 粘贴 node-token 后按 Ctrl-D 结束

export TMPDIR=/var/tmp
curl -sfL https://get.k3s.io | sudo \
  K3S_URL="https://gz.butcoder.com:6443" \
  K3S_TOKEN_FILE="/etc/rancher/k3s/node-token" \
  INSTALL_K3S_EXEC="agent" \
  sh -
```

> 备注：在当前 k3s 版本中，`agent --no-flannel` 不是有效参数；是否启用 flannel 由 `gz` 的 server 参数 `--flannel-backend=none` 决定。

验证：

```bash
kubectl get nodes -o wide
kubectl get pods -A -o wide
```

##### 2.3.7.1 离线安装/升级（chart 与镜像不可达时）

常见阻塞：

- master 无法访问 chart 下载地址
- master 无法拉取 `docker.io` / `ghcr.io` 镜像

建议策略（以本仓库为 source of truth）：

1) chart：使用 repo 内 vendored 包（或从可达机器下载后转存）
   - `infra/platform/traefik/charts/traefik-39.0.7.tgz`
   - `infra/platform/authelia/charts/authelia-0.10.50.tgz`
2) 镜像：必要时在可达节点预拉并通过代理出口复用 `sg`；对 `gz` 已落地 `k3s/containerd -> 127.0.0.1:11081 -> sg` 的镜像拉取路径
3) 如需要完全离线，可在可达机器导出镜像 tar，再传到目标节点用 `k3s ctr images import`

参考执行记录见：

- `infra/changes/20260301-k3s-init.md`
- `infra/changes/20260405-gz-k3s-image-pull-via-sg-proxy.md`

### 2.4 跨节点连通性测试（必须）

目标：验证跨节点 `PodIP` 与 `ClusterIP` 都可达。

示例（假设已给节点打了 `region` label）：

```bash
kubectl create ns net-test --dry-run=client -o yaml | kubectl apply -f -

cat <<'EOF' | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: echo
  namespace: net-test
spec:
  replicas: 1
  selector:
    matchLabels:
      app: echo
  template:
    metadata:
      labels:
        app: echo
    spec:
      nodeSelector:
        region: sg
      containers:
        - name: echo
          image: hashicorp/http-echo:0.2.3
          args:
            - "-listen=:5678"
            - "-text=hello-from-sg"
          ports:
            - containerPort: 5678
EOF

cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Service
metadata:
  name: echo
  namespace: net-test
spec:
  selector:
    app: echo
  ports:
    - name: http
      port: 5678
      targetPort: 5678
EOF

cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: curl-gz
  namespace: net-test
spec:
  nodeSelector:
    region: gz
  containers:
    - name: curl
      image: curlimages/curl:8.5.0
      imagePullPolicy: IfNotPresent
      command: ["sleep", "3600"]
EOF

kubectl -n net-test rollout status deploy/echo --timeout=180s
kubectl -n net-test wait --for=condition=Ready pod/curl-gz --timeout=180s

kubectl -n net-test get pod,svc -o wide

SVC_IP="$(kubectl -n net-test get svc echo -o jsonpath='{.spec.clusterIP}')"
POD_IP="$(kubectl -n net-test get pod -l app=echo -o jsonpath='{.items[0].status.podIP}')"

kubectl -n net-test exec curl-gz -- curl -sS --max-time 5 "http://${SVC_IP}:5678"
kubectl -n net-test exec curl-gz -- curl -sS --max-time 5 "http://${POD_IP}:5678"
```

清理：

```bash
kubectl delete ns net-test
```

### 4.3 跨地域：固定 WireGuard endpoint（推荐）

```bash

# 触发重建（可选）
kubectl -n kube-system delete pod -l app.kubernetes.io/name=kilo
```

验证：

```bash
kubectl get nodes -o json | jq -r '.items[] | .metadata.name as $n | .metadata.annotations["kilo.squat.ai/endpoint"] as $ep | .metadata.annotations["kilo.squat.ai/force-endpoint"] as $fep | "\($n)\tendpoint=\($ep)\tforce-endpoint=\($fep)"'
ssh gz.butcoder.com "sudo wg show || true"
ssh sg.butcoder.com "sudo wg show || true"
```

## 5. 备份与换 Master（SQLite + token + tls）

> k3s 官方说明：SQLite 备份除了 `server/db`，还必须备份 `server/token`，否则恢复不可用。

### 5.1 备份策略

- 必备：
  - DB：`${K3S_DATA_DIR:-/var/lib/rancher/k3s}/server/db/`
  - Token：`${K3S_DATA_DIR:-/var/lib/rancher/k3s}/server/token`
- 推荐额外备份（换机更省事）：
  - TLS：`${K3S_DATA_DIR:-/var/lib/rancher/k3s}/server/tls/`

### 5.2 备份脚本（演练一次）

本仓库提供脚本：`infra/k3s/scripts/k3s-backup.sh`

示例（在操作机执行）：

```bash
scp infra/k3s/scripts/k3s-backup.sh gz.butcoder.com:~/k3s-backup.sh
ssh gz.butcoder.com "chmod +x ~/k3s-backup.sh && ~/k3s-backup.sh"
```

### 5.3 换 Master 恢复最小流程（摘要）

1. 旧 master 做最终备份（db + token + tls）
2. 新 master 创建同版本 Ubuntu / 同版本 k3s（版本必须一致）
3. 新 master 安装 k3s（安装完成后先 `systemctl stop k3s`）
4. 将备份恢复到 `${K3S_DATA_DIR:-/var/lib/rancher/k3s}/server/`（覆盖 `db/`、`token`、可选 `tls/`）
5. `systemctl start k3s`
6. 更新 DNS / Endpoint（让 `gz.butcoder.com:6443` 指向新 master）
7. 验证 worker 自动重连：`kubectl get nodes`

## 6. 新增/移除/替换节点 SOP

### 6.1 新增 worker（sg 或未来 NUC）

1. 端口：确保能访问 `https://gz.butcoder.com:6443`
2. 安装 agent（参考 2.3.5）
3. 标注 label/taint/annotation（尤其是 NAT keepalive）
4. 做一次跨节点连通性测试（参考 2.4）

### 6.2 移除 worker（干净下线）

在 master：

```bash
kubectl drain <NODE> --ignore-daemonsets --delete-emptydir-data --force
kubectl delete node <NODE>
```

在该 worker（卸载脚本路径以安装后为准）：

```bash
command -v k3s-agent-uninstall.sh || true
sudo find / -maxdepth 4 -name "k3s-agent-uninstall.sh" 2>/dev/null | head
sudo k3s-agent-uninstall.sh
```

### 6.3 替换 worker（先加新后删旧）

- 新节点加入并 Ready
- 迁移负载：cordon/drain 旧节点
- 删除旧节点并卸载 agent

## 7. 常见故障（速查）

- `kubectl get pods -A` 大量 Pending
  - 检查是否已安装 Kilo（`kube-system` 下 `ds/kilo` 是否 running）
  - 查看 `kube-system` 下的 Kilo 日志：`kubectl -n kube-system logs -l app.kubernetes.io/name=kilo --tail=200`
- agent 加入失败（连不上 6443）
  - 检查 `infra/03-端口与安全组.md` 的 6443 放通策略；在 sg 上 `curl -k https://gz.butcoder.com:6443/ping`
- WireGuard 不通/延迟大
  - 两边执行：`sudo ss -lunp | grep -i udp`、`sudo wg show`（如可用）
  - 查看 Kilo 日志：`kubectl -n kube-system logs -l app.kubernetes.io/name=kilo --tail=200`
- 容器镜像拉取失败（尤其是 `docker.io`）
  - 现象：`ErrImagePull` / `ImagePullBackOff`
  - `gz` 优先检查 `k3s` 服务代理是否存在：
    - `ssh gz.butcoder.com "sudo cat /etc/systemd/system/k3s.service.env"`
    - `ssh gz.butcoder.com "sudo systemctl cat k3s | grep -n EnvironmentFile"`
  - 快速验证代理链路：
    - `ssh gz.butcoder.com 'curl --proxy "http://edge-user:<password>@127.0.0.1:11081" https://api.ipify.org'`
    - 期望出口 IP 为 `43.156.60.56`
  - 快速验证 containerd 拉取：
    - `ssh gz.butcoder.com "sudo k3s crictl pull docker.io/library/hello-world:latest"`
    - `ssh gz.butcoder.com "sudo k3s crictl pull ghcr.io/stefanprodan/podinfo:6.7.1"`
  - 若代理链路不可用，再考虑 registry mirror 或离线导入关键镜像
- PodIP/ClusterIP 跨节点不通（但在节点上 `curl` 可通）
  - 常见原因：`gz` 的 `iptables FORWARD` 默认策略为 `DROP`，导致 Pod 出站转发被丢弃
  - 检查：`ssh gz.butcoder.com "sudo iptables -S FORWARD | head -n 1"`
  - 修复：
    - 临时：`ssh gz.butcoder.com "sudo iptables -P FORWARD ACCEPT"`
    - 持久化：在 `gz` 安装并启用 `iptables-forward-accept.service`（见变更单 `infra/changes/20260301-k3s-init.md`）
- `kubectl logs/exec` 报 kubelet TLS 校验失败（x509 SAN 不匹配）
  - 常见原因：误把 `gz` 的 `node-ip` 配置为公网 IP（但公网 IP 不在网卡上）
  - 处理：删除 `gz:/etc/rancher/k3s/config.yaml` 中的 `node-ip`，保留 `advertise-address` + `node-external-ip`，重启 k3s
- 节点磁盘满导致只读（ro）
  - 现象：写文件失败、k3s 异常
  - 处理：清理磁盘 → 确认根分区回到 `rw` → 重启 k3s
