# 03-端口与安全组（最小开放）

目标：只开放集群运行所必须的端口；除非有独立变更单与专门架构文档，否则**默认不对公网开放任何“通用代理/管理入口”**。

> 本文件记录“应开端口 + 实测端口”。实测以运行后在节点上执行 `ss -lntup` / `ss -lunp` / `wg` 为准。

## 必开（两节点：sg → gz）

- k3s API：`6443/tcp`
  - 流向：`sg` 必须能访问 `gz:6443`
  - 安全组策略：仅允许 `sg` 的公网 IP（或固定出口）访问；不要全网放开

## Kilo / WireGuard（节点间 UDP）

- 端口：**以实测为准**
  - 记录方法：
    - 在两台节点分别执行：`sudo ss -lunp | grep -i udp`
    - 如已安装 `wireguard-tools`：`sudo wg show`
  - 将最终开放的 UDP 端口记录到此处（并限制来源为对端节点 IP）

实测（2026-03-01）：

- gz：`51820/udp`（`wg show` 显示 interface `kilo0` listening port `51820`）
- sg：`51820/udp`（`wg show` 显示 interface `kilo0` listening port `51820`）

> 备注：跨地域场景下，如果节点间私网 IP 不可路由，Kilo 可能会自动选择私网作为 endpoint，导致互联失败。
> 需要在节点上显式设置：`kilo.squat.ai/force-endpoint=<PUBLIC_IP>:51820`（见 `infra/02-集群搭建.md`）。

## Web 入口（当前方案）

当前公网 Web 入口已经切到 `Traefik + Gateway API`，由入口节点直接占用 `80/443`。

当前默认挂在这条入口上的公共认证链路是：

- `Traefik`
- `Authelia`
- 具体接入方式见 `infra/07-公网访问与统一认证链路.md`

需要开放：

| 端口 | 协议 | 用途 | 归属 |
|---:|---|---|---|
| 80 | TCP | Traefik HTTP 入口 | `traefik`（hostPort） |
| 443 | TCP | Traefik HTTPS 入口 | `traefik`（hostPort） |

> 前提：入口节点宿主机 `80/443` 不能被其他进程占用。

## Edge Gateway（当前已上线）

当前已上线 `Phase 1` 跨地域代理网关：

- 广州 `gz` 对公网监听
- 新加坡 `sg` 仅绑定 `Kilo IP 10.4.0.2`
- 架构与运维见：
  - `infra/06-跨地域代理网关架构.md`
  - `infra/platform/edge-gateway/README.md`

当前需要开放：

| 端口 | 协议 | 用途 | 归属 |
|---:|---|---|---|
| 11080 | TCP/UDP | SOCKS5 | `edge-ingress-gateway`（gz hostNetwork） |
| 11081 | TCP | HTTP CONNECT | `edge-ingress-gateway`（gz hostNetwork） |
| 18388 | TCP/UDP | Shadowsocks | `edge-ingress-gateway`（gz hostNetwork） |

说明：

- `sg` 不需要向公网开放这些端口；其代理服务只监听 `10.4.0.2`
- 若云安全组无法做“按网卡绑定”区分，应在 `sg` 侧保持这些端口默认关闭公网入口
- `gz:11081` 当前除客户端使用外，也被 `gz` 宿主机上的 `k3s/containerd` 复用为本地 HTTP CONNECT 出口代理

## 不建议公开暴露

- 未经单独评审的“通用代理”（HTTP/SOCKS）服务
- kubeconfig / kube-apiserver 的非必要公网访问
- 运维面板（如未来安装的 Dashboard / Argo / Grafana 等）默认先走内网或 SSH 端口转发
